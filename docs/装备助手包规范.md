# 装备助手包规范与安装选项设计

版本：v1（草案）　日期：2026-11-21　涉及工程：MockController（发布/分发）、MockRunner（下载与安装）

## 一、要解决的问题

装备助手现在只有一种落地方式：Runner 把包内文件逐个下载到 `assistant_shelf/installed/<id>/`，再按 `entry`（`start.bat` / `.exe` / `.py`）启动。但实际交付物有三类：

| 类型 | 典型形态 | 现有实现能否处理 |
| --- | --- | --- |
| 免安装绿色包 | 自带运行时，`runtime/xxx.exe` 直接启动 | 能（`camera-assistant` 即此类） |
| 自带安装脚本 | 包内有 `install.ps1` / `setup.bat`，需执行后才能用 | 不能，脚本不会被执行 |
| 独立安装程序 | `setup.exe` / `.msi`，需静默安装到系统目录、写注册表 | 不能，只能当普通文件拷过去 |

目标：**包自己声明「怎么装」，Runner 提供统一的安装选项并如实执行**，三类包在货架上表现一致，现场操作一致。

## 二、核心原则

1. **安装方式属于包，不属于调用方**：由发布者在包 manifest 里声明，Runner 不得自行猜测。
2. **默认安全**：不写 `install` 字段一律按「免安装」处理，行为与现在完全一致；执行安装器或脚本属于高风险动作，必须先经用户确认。
3. **安装即事实**：安装结果写 `install.json`（实际安装目录、启动命令、卸载命令、验收结果），后续启动/卸载/升级只认这份记录。
4. **可验收、可回滚**：安装后跑 probe；失败不写「已安装」状态，保留 staging 供排查。

## 三、包类型与安装语义

| `install.kind` | 含义 | Runner 动作 |
| --- | --- | --- |
| `portable`（缺省） | 免安装，解包即可用 | 解包到安装目录 → 写记录 → 可直接启动 |
| `script` | 自带安装脚本 | 解包到 staging → 在 staging 执行脚本 → 脚本产出视为安装结果 |
| `installer` | 独立安装程序（exe 或 msi） | 解包 → 以静默参数执行安装器 → 等待退出码 → 探测实际安装目录 → 验收 |

`script` 与 `installer` 的区别：前者在包目录内就地完成（通常是复制文件、建快捷方式、注册环境），后者由第三方安装引擎接管（可写系统目录、注册表、服务）。

## 四、manifest 字段规范

在现有 manifest（`id/name/version/vendor/summary/description/tags/requires/release_note/published_at/entry/self_contained/icon_file/files`）基础上，新增 `install` 对象：

```json
"install": {
  "kind": "installer",
  "requires_admin": true,
  "timeout_s": 900,
  "probe": { "script": "probe.ps1", "timeout_s": 30, "expect_exit_code": 0 },
  "portable": { "entry": "start.bat", "runtime_exe": "runtime/App.exe" },
  "script": {
    "path": "install.ps1",
    "interpreter": "powershell",
    "args": ["-ExecutionPolicy", "Bypass", "-File", "{script}"],
    "cwd": ".",
    "env": { "ATE_INSTALL_DIR": "{install_dir}" }
  },
  "installer": {
    "path": "setup.exe",
    "engine": "nsis",
    "silent_args": ["/S", "/D={install_dir}"],
    "success_codes": [0, 3010]
  },
  "uninstall": {
    "path": "uninstall.exe",
    "args": ["/S"],
    "remove_dir": true
  }
}
```

字段说明：

| 字段 | 适用 | 说明 |
| --- | --- | --- |
| `kind` | 全部 | `portable` / `script` / `installer`，缺省 `portable` |
| `requires_admin` | script / installer | 需要提权时 Runner 以 UAC 方式启动，前端需先提示 |
| `timeout_s` | script / installer | 安装总超时，超时杀进程组并判失败 |
| `probe` | 全部 | 安装后验收脚本，输出单行 JSON 或退出码 |
| `portable.entry` | portable | 启动入口（回退顶层 `entry`，再回退 `start.bat`） |
| `portable.runtime_exe` | portable | 自带运行时程序，优先于 entry 直接启动 |
| `script.path` / `interpreter` / `args` / `cwd` / `env` | script | 脚本及其执行参数；`args` 与 `env` 由包声明，**Runner 不接受调用方传入** |
| `installer.path` / `engine` / `silent_args` / `success_codes` | installer | 安装器与其静默参数；`engine` 只影响目录探测方式（nsis/inno/msi/unknown） |
| `uninstall.*` | 可选 | 卸载命令与是否删除安装目录 |

占位符（只在 `args` / `env` / `silent_args` 中替换）：

| 占位符 | 含义 |
| --- | --- |
| `{install_dir}` | Runner 分配的安装目录（Windows 路径） |
| `{package_dir}` | staging 解包目录 |
| `{script}` | 脚本文件完整路径 |
| `{installer}` | 安装器完整路径 |
| `{id}` / `{version}` | 助手标识与版本 |

三种典型包的写法：

```json
// 免安装绿色包（现有 camera-assistant）
"install": { "kind": "portable", "portable": { "runtime_exe": "runtime/CameraAssistant.exe" } }

// 自带安装脚本
"install": {
  "kind": "script", "requires_admin": false, "timeout_s": 300,
  "script": { "path": "install.ps1", "interpreter": "powershell",
              "env": { "ATE_INSTALL_DIR": "{install_dir}" } }
}

// 独立安装程序（NSIS 静默）
"install": {
  "kind": "installer", "requires_admin": true, "timeout_s": 900,
  "installer": { "path": "setup.exe", "engine": "nsis",
                 "silent_args": ["/S", "/D={install_dir}"], "success_codes": [0] },
  "probe": { "script": "probe.ps1", "timeout_s": 30 }
}
```

## 五、Runner 安装流程

```
下载清单 → 取包（逐文件 + sha256 校验）
        → staging：assistant_shelf/staging/<id>-<时间戳>/    ← 未成功前不碰 installed
        → 分支执行（portable / script / installer）
        → probe 验收
        ├─ 通过：staging 落到 installed/<id>/ + 写 install.json → 状态 installed
        └─ 失败：install.json 记 install_failed + 错误明细，installed 保持原状（升级场景）或不存在
        → 清理 staging（可选 keep_failed 保留）
```

安装状态机（对前端暴露）：

| 状态 | 含义 | 前端表现 |
| --- | --- | --- |
| `not_installed` | 未下载 | 「下载」按钮 |
| `downloading` | 下载中 | 进度条（文件数/字节数） |
| `installing` | 执行安装器/脚本 | 转圈 + 「正在安装，请勿关闭窗口」 |
| `installed` | 已安装 | 「启动」+「移除」 |
| `install_failed` | 安装失败 | 「重试」+ 查看日志 |
| `needs_admin` | 需要提权但被拒绝 | 提示以管理员身份重启 Runner |

`installed/<id>/install.json` 记录（新增字段加粗表示相对现有实现新增）：

```json
{
  "id": "therm-helper", "name": "温控助手", "version": "1.2.0",
  "kind": "installer",
  "entry": "app/ThermHelper.exe",
  "install_dir": "D:\\ATE\\MockRunner\\backend\\assistant_shelf\\installed\\therm-helper\\app",
  "launch": { "exe": "app/ThermHelper.exe", "args": [], "cwd": "app" },
  "uninstall": { "path": "app/uninstall.exe", "args": ["/S"], "remove_dir": true },
  "verify": { "ok": true, "detail": "probe exit 0", "at": "2026-11-21 18:20:00" },
  "source": "controller", "source_url": "http://127.0.0.1:8070",
  "installed_at": "2026-11-21 18:19:40", "elapsed_s": 46
}
```

启动优先级（`launch()` 按序判断，命中即止）：

1. `install.json.launch.exe`（安装后确定的启动程序）
2. `manifest.install.portable.runtime_exe`
3. `install.json.entry` → `manifest.entry` → `start.bat`
4. 都不可用：报错并提示「该助手未提供可执行入口」

## 六、Controller 侧变更

1. **发布校验**（`assistants.py` 的 `_make_manifest` / 发布接口）：
   - `kind` 只允许三种值；缺省补 `portable`；
   - `script.path` 必须存在于 `files`，后缀限 `.ps1/.bat/.cmd/.py`；
   - `installer.path` 必须存在，后缀限 `.exe/.msi`；
   - `portable.entry` / `runtime_exe` 必须存在；`entry` 顶层字段继续兼容；
   - `installer.engine=msi` 时 `path` 必须是 `.msi`；
   - `requires_admin` 为真时，清单接口透出该标记，供 Runner 提前提示；
   - 所有包内文件继续记 `sha256`，安装器文件不例外。
2. **清单透出**：`GET /api/v1/assistants` 每条增加
   ```json
   "install": { "kind": "installer", "requires_admin": true, "installer": "setup.exe" }
   ```
   （只透出不敏感的摘要字段，完整块走详情接口）
3. **发布示例**：`POST /api/v1/assistants` 的 `assistant.install` 与 `files` 一并提交，校验失败返回 400 并列出全部问题。

## 七、Runner API 变更

| 接口 | 变更 |
| --- | --- |
| `POST /api/assistants/install` | body 扩展为 `{ "id": "...", "options": { "install_dir": "…", "silent": true, "keep_failed": false } }`；`options` 全部可选，且**只能影响目录与日志保留**，不能改变安装方式或命令行 |
| `GET /api/assistants/install-status/{id}` | 新增，返回 `{state, stage, progress, error, elapsed_s}`，前端轮询（1s） |
| `POST /api/assistants/launch` | 按 install.json 的 launch 决策，不再只看 entry |
| `POST /api/assistants/uninstall` | 若包声明 `uninstall` 先执行卸载命令（超时 120s），成功后再把目录归档到 `installed/_removed/` |

错误码约定：`invalid_kind`、`package_missing`、`probe_failed`、`installer_failed(exit=n)`、`timeout`、`needs_admin`、`path_escape`。

## 八、前端交互（Runner 货架）

1. 卡片按 `install.kind` 显示徽标：「免安装」「安装脚本」「安装程序」，需提权的加「需管理员」；
2. 「下载」按钮文案随类型变化：免安装→「下载」，脚本/安装程序→「安装」；
3. 点「安装」先弹确认：显示安装方式、预计大小、是否需要管理员、安装目录（可改）；
4. 安装中禁用该行其它操作，展示阶段文案（下载 → 校验 → 安装 → 验收）；
5. 失败展示错误码与「查看安装日志」，日志落 `assistant_shelf/logs/<id>-<时间戳>.log`；
6. 安装完成刷新为「启动」「移除」，并在详情里显示版本、安装时间、验收结果。

## 九、安全与合规

| 风险 | 措施 |
| --- | --- |
| 远端下发任意命令 | 命令行只能来自包 manifest，调用方 `options` 不得注入参数；白名单占位符替换 |
| 路径穿越 | `script.path` / `installer.path` / `cwd` 解析后必须落在包目录内 |
| 提权滥用 | `requires_admin` 必须显式声明；Runner 以 UAC 启动并记录 `elevated: true` |
| 挂起的安装器 | `timeout_s` 超时后杀进程树（`taskkill /T /F`），并记 `timeout` |
| 恶意包 | 建议发布时对 `setup.exe` 做 Authenticode 签名并在 Controller 侧记录证书主体；Runner 仅展示不强制 |
| 半装状态 | staging 隔离，失败不污染 `installed/`；升级失败保留旧版本 |

## 十、兼容与迁移

1. 现有 6 个助手全部按 `kind=portable` 处理（`camera-assistant` 走 `runtime_exe`，其余走 `entry`），行为不变；
2. 不写 `install` 字段 = `portable`，老包无需改动即可继续下载使用；
3. `install.json` 老记录缺 `kind` 时按 `portable` 兼容读取；
4. Controller 旧 manifest（无 `install`）在清单接口补默认值，不写回文件。

## 十一、分期落地

| 期 | 内容 | 验收 |
| --- | --- | --- |
| P0 | manifest `install` 字段 + Controller 发布校验 + 清单透出 + 前端徽标文案 | 三类包都能发布，缺字段/文件不存在被拒 |
| P1 | Runner `portable` / `script` 分支 + staging + install.json + 安装状态接口 | 绿色包与脚本包安装成功、可启动；脚本失败不写已安装 |
| P2 | `installer` exe/msi + 静默参数 + 退出码 + 安装目录探测 + probe 验收 | exe/msi 静默安装成功并能启动；probe 失败判失败 |
| P3 | 卸载、升级覆盖、失败回滚、安装日志、需管理员确认弹层 | 卸载后可重装；升级失败保留旧版本 |

## 十二、验收用例

| 用例 | 期望 |
| --- | --- |
| 绿色包（camera-assistant）安装 | `kind=portable`，直接启动，`install.json.kind=portable` |
| 脚本包 `install.ps1` 成功 | 脚本被执行（产出文件落在 install_dir），状态 `installed` |
| 脚本包返回非 0 | 状态 `install_failed`，`error=installer_failed(exit=N)`，不写已安装 |
| NSIS 静默安装 | `setup.exe /S /D=...` 执行，退出码 0，探测到目录，probe 通过 |
| msi 静默安装 | `msiexec /i ... /qn`，成功码含 3010（需重启）时提示重启但不判失败 |
| 安装器卡死 | 超时后杀进程树，状态 `install_failed`，`error=timeout` |
| 需要管理员但拒绝 | 状态 `needs_admin`，提示以管理员身份重启 |
| 包内路径 `..\..\evil.ps1` | 发布或安装阶段拒绝，`error=path_escape` |
| 卸载 | 执行卸载命令 → 目录归档到 `_removed` → 可重新安装 |

## 十三、非目标

1. 不做静默参数的自动探测（必须包声明，避免装错参数）；
2. 不做多语言安装界面处理；
3. 不在 Runner 侧做病毒扫描或签名校验强制拦截；
4. 不支持 Linux 免安装以外的安装器（当前助手均为 Windows）。
